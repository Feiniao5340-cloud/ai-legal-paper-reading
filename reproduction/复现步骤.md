## 一 无模型调用重放真实输出

在仓库根目录执行：

```text

python -X utf8 reproduction/review_cards.py --source sources/case-D.txt --result results/D-map/model-output.txt --out ../review-D
```

第一条运行七个合成边界测试，并重检三份本地方法输出与本次平台输出，两类结果分开报告。第二条实际渲染reading.md、evidence-cards.md、checks.json；不调用模型。目录须全新，已有目录拒绝覆盖。检查通过仍semantic_verified=false。

用case-E及results/E-map/model-output.txt替换参数可复现两个真实检查错误，复核CLI返回2并保留渲染材料；这不是程序故障，更不是已获得正确阅读。原文定位和修复路径见evidence/失败后怎样回查.md。

## 二 先准备实际模型输入

```text

```

只校验源文SHA256、复制本轮输入、生成完整prompt与记录，不需要账号和网络。查看source.txt、SKILL.md和protocol.md。不会读取父目录评分或旧结果，原文是材料而非指令；这是提示和文件范围约束，不是声称操作系统级隔离。

## 三 需要时重新阅读

```text
python -X utf8 reproduction/run_case.py --case D --variant map --out ../read-D --codex codex --model gpt-6-luna --reasoning max
python -X utf8 reproduction/run_case.py --case D --variant baseline --out ../read-D-base --codex codex --model gpt-6-luna --reasoning max
```

CLI须按官方方式自行配置账号和模型权限，不把凭据交给仓库。--codex可填实际可执行文件路径；换模型或选项须记录差异。case可为A、D、E；每次使用新目录。两臂自然任务相同，方法臂增加协议和输出组织，不因基线未给JSON判语义失败。

模型仅解释标准输入，原始answer.md和last_message.txt保留。方法臂在delivery输出主件、证据卡和检查。当前入口对解析或机械检查失败返回3，同时保留模型的技术完成记录；reader_markdown即使生成，也不能因此当成已核实内容。所有状态均与semantic_verified=false分开。

实际公开结果的model-output.txt为原模型字节，prompt.md为完整实际输入，run-summary.json为摘要；完整原生事件本地保留。当前仅改进了异常处理退出码及依赖路径，实际提示词未改。准备输入会与原运行指纹核对。

## 四 手工复核

先读D1或A1，再看来源锚点是否包括主语/代词承接，态度锚点是否支持该命题的具体指向；条件、例外和证据用途不能省略。原文只有预测时不能归成规范主张，已有问题不能因纠错被撤回。段号/引文命中不能判断关系是否成立。

本轮复核为本会话AI辅助、非盲，未经用户新增逐项标注。六次记录及局限见evidence/语义与开销核查.md，不能据小样本宣称普遍、稳定或提速。

## 故障处理

源哈希变化先查版本，不绕过。已存在目录换新目录，不删除旧结果。找不到CLI则指定路径；无模型权限记录失败，不换模型冒充同模型。重连、超时及不合格式输出均保留，不自动重试或放宽权限。源PDF有重复MediaBox警告，必要片段已对原页核对，不据提取成功证明整个PDF结构无问题。
